# 架构与实现

本文说明各模块的职责与几处关键机制。踩坑记录见 [打包与交付规范.md](打包与交付规范.md)。

---

## 一、运行位置

模组以 `preload-native` 形态被启动器加载，代码运行在**游戏进程内部**，拿到的是游戏的渲染线程与触摸输入。

这意味着：

- 没有 Activity，没有 View 体系，不能使用任何 Android 控件。
- 所有界面都要自己算坐标、自己画、自己判断点击落在哪里。
- 与游戏争夺同一个线程，任何耗时操作都会直接表现成掉帧。

## 二、模块划分

```
main.cpp
  ├─ 生命周期：load / enable / disable
  ├─ 模块注册（Mod Menu）
  └─ 数据目录与镜像维护

HudUi             界面核心
  ├─ 布局：三种形态的尺寸与位置
  ├─ 动画：形态切换的插值过渡
  ├─ 绘制：矩形、圆角、文字、图标、进度条
  ├─ 触摸：命中测试与拖动手势状态机
  └─ 持久化：ui.json 实时写入

RenderHook        渲染钩子，把绘制指令提交给游戏
KugouProvider     业务层：搜索 / 歌单 / 歌词 / 封面 / 登录
PlaylistProvider  歌单与播放队列
AudioEngine       音频引擎（音量、输出）
AudioPlayer       播放器状态与进度
HttpClient        本机 HTTP 客户端（含异步）
qrcodegen         二维码生成（扫码登录）
```

## 三、界面状态机

`HudUi` 维护三种形态：

| 形态 | 枚举 | 定位方式 |
|---|---|---|
| 单行条 | `Mode::Bar` | 记住 `ballX/ballY`，可拖动 |
| 中面板 | `Mode::Mini` | 记住 `miniX/miniY`，可拖动 |
| 大面板 | `Mode::Expanded` | **始终居中，不可拖动** |

拖动用 `Drag` 枚举区分对象：`Panel` / `Progress` / `List` / `ScrollThumb` / `Volume` / `AlphaSlider`。

触摸移动时若手指位移超过 8 像素且当前没有指定拖动对象，会被升级为整块面板拖动——**这一步只对可拖动形态生效**，大面板因为没有任何分支接住，天然保持不动。

## 四、绘制

所有元素用统一的绘制原语提交：填充矩形、圆角矩形、描边、文字、图片。

坐标系统一换算到屏幕像素，触摸事件进来时也做同样换算，两边必须用同一套数值，否则会出现「看得见点不中」。

图标不使用字体图标，用几何图形拼（圆、线、弧），避免依赖外部字体文件。

## 五、渲染节流

大面板元素多。如果每帧全量重建，帧率会明显下降。

节流逻辑：

1. 状态变化时置 `mDirty`。
2. 渲染循环按 `forceInterval` 决定是否重绘。
3. 动画（如歌词滚动）不直接置 `mDirty`，而是设置 `mLyricAnimating` 标志，由节流逻辑统一考虑。
4. 大面板额外加 33 ms 下限。

早期版本在动画里直接置 `mDirty = true`，绕过了节流，表现就是「大面板一开就卡」。

## 六、音乐数据通路

```
HudUi  ──调用──> KugouProvider ──HTTP──> 127.0.0.1:<随机端口>
                                              │
                                     本地服务库（同进程内）
                                              │
                                        平台接口
```

服务库在模组进程内监听一个随机端口，端口号回传给模组。业务层只发 HTTP，不关心签名与设备指纹。

这样做的好处：平台相关逻辑被隔离在一个库内，界面部分可以独立演进。

## 七、服务库的加载

见 [打包与交付规范.md](打包与交付规范.md) 第三节。要点：

1. 服务库以二进制段形式内嵌在主 `.so` 里（编译期 `objcopy`）。
2. 运行时按 64 KB 分块写到应用私有目录。
3. `chmod 0500` 后 `dlopen`。
4. 已存在且大小一致则直接复用，不重复写盘。

**不能**从外部存储直接 `dlopen`，Android 14 会拒绝。

## 八、数据持久化

### 主数据目录

```
<模组目录>/data/
  ├─ ui.json          面板位置、形态、主题、透明度、字号、开关
  ├─ session.json     登录令牌（绝不分发）
  ├─ progress.json    播放进度
  └─ device_info.json 设备指纹
```

### 镜像目录（防更新丢数据）

启动器更新模组时会整个替换模组目录，`data/` 会一起消失。

对策：在模组目录**之外**再维护一份镜像。

```
<minecraft>/MusicModData/
```

- 每次保存后同步写镜像。
- 启动时若主数据缺失或为空，从镜像恢复。

这段逻辑改动时必须同步核对，否则玩家升级一次就丢令牌。

## 九、配置项

模组菜单里可调的项目（`pl::modmenu::ConfigEntry`）：

| key | 类型 | 说明 |
|---|---|---|
| `showCover` | Toggle | 显示封面 |
| `showProgress` | Toggle | 显示进度条 |
| `autoPlay` | Toggle | 自动播放 |
| `uploadListen` | Toggle | 上报收听（影响平台推荐） |
| `sourceKugou` | Toggle | 音乐源：酷狗 |
| `sourceYoutube` | Toggle | 音乐源：YouTube |
| `language` | Enum | 界面语言 |
| `lyricDelay` | SliderInt | 歌词延迟偏移 |
| `fontScale` | SliderFloat | 字号缩放 |
| `volume` | SliderInt | 音乐音量 |

位置类配置（`panelX` / `panelY`）已经删除。它们原本直接改写运行时插值坐标，下一次布局就会被覆盖，属于无效实现；面板位置改为由拖动决定并自动保存。

## 十、失败模式与排查

| 现象 | 首查位置 |
|---|---|
| 界面完全不出现，但日志有音乐 | `modId` 是否等于目录名（注册失败） |
| 界面出现但点不中 | 触摸坐标换算与绘制坐标是否一致 |
| 面板一开就卡 | 是否有动画绕过节流置脏 |
| 无法播放，日志有 linker 报错 | 服务库落盘位置（必须是私有目录） |
| 升级后令牌丢失 | 镜像目录逻辑是否生效 |
| 拖动后松手弹回 | 布局函数是否强制覆盖了位置 |
