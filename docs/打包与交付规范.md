# 打包与交付规范

> 本文是硬规则，不是建议。每次出包前逐条核对，不允许凭记忆。
>
> 修订记录：早期版本里「往 .so 尾部追加数据」和「runtime.zip 随包」两条**都是错的**，已作废；
> 「modId 必须等于 manifest 的 name」也是错的，正确规则见第二节。

---

## 一、绝不要往 `.so` 尾部追加数据

**现象**：模组完全失效——面板、按钮全都没有，但日志里音乐逻辑照跑（心跳、搜歌、歌词、封面全都正常）。极易误判成「模组没加载」。

**原因**：尾部追加会让 ELF 后面挂一坨非段数据，宿主加载环节不接受这种形态。

参考模组 MagicPort 2.6.3 的 `build.sh` 原话：

```
# 运行时不再追加到 .so 尾部（尾部内嵌形态已废弃）
```

**正确做法**：用 `objcopy` 把服务库转成 `.o` 一起链接（见第三节）。

---

## 二、`modId` 必须等于模组**目录名**

这是最容易踩、后果最误导人的一条。

报错原文：

```
E Preloader: Rejected Mod Menu module musicmod.hud:
  declared mod_id X does not match owning lifecycle mod Y
E MusicMod: 界面: 模块注册失败
I MusicMod: 步骤: 界面注册结果=0
```

**规则**：`pl::modmenu::ModuleInfo::modId` 必须与宿主认定的 owning lifecycle mod 完全一致，
而这个名字是 **`mods/` 下的目录名**，不是 `manifest.json` 里的 `name`。

**为什么不能硬编码**：不同启动器实例、不同导入方式会让目录名不一致。
实测同一台设备上三个实例，一个目录叫 `沉浸播放`，另外两个叫 `MusicMod`。
写死任何一个值，都会在部分实例上失败。

**正确做法**：运行时从 `ctx.modRootPath()` 取最后一段路径。

```cpp
// load(pl::mod::ModContext &ctx) 里取，存成员变量
const std::string root = ctx.modRootPath().string();
const std::size_t slash = root.find_last_of('/');
const std::string dirName =
    (slash == std::string::npos) ? root : root.substr(slash + 1);
if (!dirName.empty()) {
  mModDirName = dirName;
}

// enable() 里注入（ctx 不在这个作用域，必须走成员变量）
if (!mModDirName.empty()) {
  mUi.setModId(mModDirName);
}
```

| 项目 | 说明 |
|---|---|
| `manifest.json` 的 `name` | 显示名，随便叫什么都行 |
| `HudUi.cpp` 的 `info.modId` | **目录名**，必须动态取 |
| 日志标签 `kTag` | 与注册无关，不影响功能 |

改完后日志应出现：

```
界面: 已注册, 屏幕=..., modId=<实际目录名>
步骤: 界面注册结果=1
```

如果是 `界面注册结果=0`，就是这条错了。

> 陷阱：模组失败时音乐、歌词、封面全部正常，只有界面不出现。
> 不要因为「日志里有音乐」就认定模组加载成功。

## 三、内嵌方式：objcopy，不用尾部追加、不用 runtime.zip

1. `objcopy -I binary -O elf64-littleaarch64` 把 `libkugou_server.so` 转成 `embed/libkugou_blob.o`
2. CMakeLists 里作为源文件一起链接
3. 运行时定位符号 `_binary_libkugou_server_so_start` / `_end`
4. 分块（64 KB）写到**应用私有目录**并 `chmod 0500`，再 `dlopen`

**为什么必须写私有目录**：Android 14 起不允许从可写位置 dlopen 库。
模组目录在 `Android/media/...`（外部存储），属可写位置，会被 linker 拒绝：

```
E/linker: library ".../mods/MusicMod/data/libkugou_server.so"
          is not accessible for the namespace "classloader-namespace"
```

启动器会把模组复制到 `/data/data/<pkg>/cache/native_mods/...` 再加载，
`selfDir()` 拿到的正是这个路径——私有、可写、允许 dlopen。

**验证内嵌是否生效**：

```bash
nm build/final/libmusicmod.so | grep _binary_libkugou_server_so_size
# 本项目为 00000000003e4e20，即 4083232 字节
```

## 四、构建流程

```bash
sh build.sh
```

产物：

| 路径 | 说明 |
|---|---|
| `build/libmusicmod.so` | cmake 原始输出 |
| `build/final/libmusicmod.so` | 成品，约 5.3 MB，自包含 |
| `build/final/runtime.zip` | 兜底用，**不必放进包** |

---

## 五、打包

```bash
python3 tools/pack_levipack.py \
    --so build/final/libmusicmod.so \
    --manifest manifest.json \
    --dir MusicMod \
    --out dist/MusicMod.levipack
```

`levipack` 就是 zip 改后缀。包内结构：

```
MusicMod/
MusicMod/libmusicmod.so
MusicMod/manifest.json
```

**包内只需这两个文件。** 不要放 `runtime.zip`（内嵌已足够），不要放 `data/`。

---

## 六、出包前必查四项

```bash
# 1) 包内 so 数量必须等于 1
unzip -l xxx.levipack | grep -c '\.so'

# 2) 内嵌服务库符号存在且大小正确
nm /tmp/vf/MusicMod/libmusicmod.so | grep '_binary_libkugou_server_so_size'

# 3) 版本号与包内 manifest 一致
unzip -p xxx.levipack 'MusicMod/manifest.json' | grep version

# 4) 包内不含玩家数据
unzip -l xxx.levipack | grep -E 'session|ui\.json|data/'   # 应无输出
```

## 七、绝对不能进包的东西

- `data/session.json`（登录令牌）
- `data/ui.json`（玩家设置）
- `data/` 下任何封面缓存、日志
- 工作区根目录的 `qr*.json`、`qr_key_live.txt`、`wx_uuid.txt` 等扫码临时文件

**令牌外泄不可挽回。** 包里只放两个文件，天然不会带出去。

发版前额外核对一次：仓库和包里都不能出现 `userid`、`vip_token` 的真实值。

---

## 八、部署与目录名

模组目录模板：

```
<外部存储>/Android/media/<启动器包名>/minecraft/<实例>/mods/<目录>/
```

**部署只覆盖 `libmusicmod.so` 和 `manifest.json`，绝不要动 `data/` 目录**，否则令牌和设置全丢。

正因为目录名不统一（见第二节），部署前先 `ls` 确认实际名字，不要凭记忆写死。

---

## 九、数据防丢：镜像目录

启动器更新模组时会**整个替换** `mods/<目录>`，`ui.json`、`session.json` 会一起消失。

对策是在模组目录**之外**再存一份镜像：

```
.../minecraft/MusicModData/     <- 镜像，与 mods 同级
```

- 每次保存后同步写镜像
- 启动时若主数据缺失或为空，从镜像恢复
- 覆盖的文件：`ui.json`、`session.json`、`progress.json`、`device_info.json`

改动数据目录结构时，必须同步检查这段逻辑，否则玩家升级一次就丢令牌。

## 十、通过 adb 导入 levipack 不可用

```
am start -a android.intent.action.VIEW -d file:///... -t application/zip
```

会被拒绝，报「非法 ZIP 模组包：必须包含 manifest.json 与 .so」。

已做对照实验：历史上成功导入过的旧包走同一路径也报同样错误，
说明该通道本身不可用，与包内容无关。

正确方式：启动器界面「添加模组」选文件，或直接把两个文件复制进 mod 目录。

## 十一、版本戳

位置：`src/main.cpp` 写 `build_stamp.txt` 的那段。

```cpp
stamp << "ui_version=NN\nbuild=YYYY-MM-DD HH:MM\n"
         "fix=逗号分隔的修复项\n";
```

每出一版都要改，否则无法判断设备上跑的是哪一版。

**注意区分两个版本号**：

| 位置 | 用途 |
|---|---|
| `manifest.json` 的 `version` | 给玩家和包管理器看的发布版本，如 `0.34` |
| `build_stamp.txt` 的 `ui_version` | 内部构建号，用于确认设备上实际加载的是哪一版 |
